# Whole-Work Implementation: Composition Standard

This standard defines readiness, combined evidence and whole-result conformance. SKILL.md owns controller execution/review order. Registered `implement-unit`'s IMPLEMENTATION.md supplies executable source gates, code/test/runtime criteria and delivery content; it is already required by the controller and is not restated here. `artifact-layout` owns artifact paths, names, purposes and ownership; SKILL.md owns write permission and approval validity. Record-schema loading is controlled by the stage's actual record gate, not this content standard. Standards import no author workflows.

## One execution basis

Accept an authorized approved ticket set or entire bounded approved direct change under the unit standard's gates. Resolve child inputs to the governing root and exact selected sources. Heavyweight work has one root global ticket set, controller and delivery; a child returns to that root. Direct work has one full-scope pair and no synthetic ticket/set.

Use one identified workspace with actual prerequisite outputs. Serial work is the default: missing dependency edges do not imply safe parallelism where files, state, fixtures or contracts overlap. Respect repository policy and unrelated user work; do not invent branching/worktrees/merges/commits or deployment requirements.

Ticket execution metadata is compact: current status, blocker, actual implementer/reviewer handles and evidence references. It cannot grant approval, redefine obligations or replace current code/evidence. Pending, implementing, in review, passed and blocked may use project vocabulary. Passed means current independent conformance, not final human acceptance. Every metadata mutation remains a specification write; an obsolete label never makes stale evidence usable.

The controller owns scheduling, common basis, readiness, role routing and whole-result delivery, not code repairs or substitute review. One assigned writer owns each artifact. Root definition/navigation and `implementation.review-fix-decisions.log.md` belong to the controller; ticket pairs have their existing ticket/log. The direct pair and controller share the sole implementation log through its assigned writer. Role headers are bindings, not progress ledgers.

## Readiness and evidence applicability

A unit is ready only when its required outputs are physically usable in current combined code and relevant evidence remains applicable. A status claim, isolated branch or unincorporated predecessor is insufficient. Dependent scheduling requires current independent Pass, usable incorporated output, saved report/repair dispositions and the confirmed exact ticket execution-block update. Planning approval alone does not authorize execution.

Dispatch context includes bounded unit scope and complete applicable standards/sources, selected root/shared/architecture/child references, current combined code/user-work boundary, actual prerequisite outputs, assigned verification, records/prior findings and return route. Delegates neither reconstruct the project from chat nor create competing controllers/reviewers.

Review/evidence identities include actual dirty and untracked code, not just HEAD. Intervening source, caller, state or integration changes require affected checks/review; unchanged evidence needs explicit applicability to current relevant code, participants, configuration and environment. Preserve unrelated results with an impact basis. Returning implementers reconcile current code before editing; serialize repair writers and assess a stable identified candidate.

Apply semantic invalidation immediately even if human confirmation of a blocker/status patch is pending. Source defects return to their owning authority and affected approval gate; synchronize canonical sources, root coverage and tickets only through confirmed writes. An execution log cannot authorize a different design. Retrieve accessible evidence and restore available tools before declaring a blocker. Continue other genuinely ready work only when it cannot conceal or worsen the blocker; otherwise report the exact missing condition, affected scope and external action, without a recovery/state artifact.

## Final combined result

For a **direct change**, the original unit reviewer assesses the entire target and final combined runtime/regression/macro evidence under IMPLEMENTATION.md. Its current full-change Pass is final independent review. The controller establishes scope, stable basis and evidence applicability—not another verdict. Missing/stale obligations return to that pair; no duplicate reviewer or unchanged verification is required. Explicit final human acceptance remains necessary.

For a **ticket set**, every required output must be incorporated and final composition must realize the whole authorized scope: file responsibilities, runtime collaboration, contracts/data/callers, state/resources and retirement of superseded paths. Heavyweight scope includes selected shared/child requirements, architecture, all applicable complete technical models and cross-child flows—not unrelated future map items. Local Passes cannot prove composition.

Required project regressions and every selected macro flow execute on final combined code with approved real participants and substitution limits. Earlier runs count only with explicit unchanged relevant code, participants, configuration and environment applicability. Plans, compilation, isolated mocks and sums of local Passes cannot prove actual collaboration. Unavailable mandatory execution blocks final Pass and acceptance handoff.

Overall findings identify approved responsible owners/tickets; original implementers repair on current combined code and affected unit reviewers reassess. Unowned required work or missing design returns upstream instead of creating a catch-all fixer or artificial ticket. Overall review covers the full result, not concatenated local summaries.

## Overall review coverage

Alongside applicable IMPLEMENTATION.md criteria, reports cover:

1. **Authorized coherent basis:** current source/authorization, incorporated prerequisites, preserved user work and identified combined code.
2. **Complete composition:** whole-target coverage, integrated owners/contracts and retirement of superseded paths.
3. **Ticket closure and continuity:** applicable ticket Passes, no unresolved findings and accountable original roles/handoffs.
4. **Current integrated evidence:** mandatory combined regression/macro outcomes, truthful real/substituted scope and limits.
5. **Review and acceptance integrity:** full independent assessment, accurate authority/status and artifact/write integrity.

Final Pass is the route-appropriate independent assessment, not controller aggregation. The one delivery summary uses IMPLEMENTATION.md's content/storage rules and references, rather than duplicates, the unit evidence. The reviewed whole scope still awaits explicit human acceptance; delegated unit Passes impose no intermediate acceptance gates.
