# Implement Unit

Before investigation, questions or edits, read the complete [IMPLEMENTATION.md](IMPLEMENTATION.md) and `artifact-layout`. Load reference skills by registered name through the harness; resolve stage-local files relative to this installed skill and cross-skill content through its registered owner, never guessed configuration paths; reuse intact current supplied content. Standard imports do not load owner SKILL workflows or their prerequisites. Missing required sources block work. Load registered `ask-with-context` for substantive human questions; read [reviewer-prompt.md](reviewer-prompt.md) at review dispatch.

Read `review-records` before the first submission or record creation, before finding-linked repair, or when recovering relevant existing records—not automatically for initial scope questions. Layout owns paths, names, exclusion, file purpose and single-writer ownership; records owns admitted evidence and schemas; this stage owns permission and validity.

## 1. Establish the unit and retained pair

Validate the standard's route, current approvals, execution authorization, actual incorporated prerequisites and direct-fit boundary. Inspect code/callers, repository rules, user changes and verification facilities. Resume from actual source/code/evidence and records, not status labels. Reconcile intervening changes before editing; retained context cannot restore an old snapshot.

Keep the original implementer and separate independent read-only reviewer through fixes, resumption and human revisions. Bind the reviewer at first review. Attempt real resumption/context recovery before replacing a genuinely unavailable role; explain the loss, supply current inputs and old findings, and preserve the available counterpart. Speed/disagreement never justifies replacement; missing independence or recovery capability blocks affected work.

Standalone authors establish the artifact workspace and dispatch review. Delegated authors use the controller's workspace, assigned files/log writer and return route; the controller dispatches the same pair, not another controller or reviewer. Initial/replacement implementers receive this flow, complete applicable standards, approved sources/approval and original requirement evidence, current code/user-work boundary, actual prerequisites, assigned verification, records and prior findings before choices or edits. Delegated specification writes also require the exact confirmed patch/basis and confirmation reference.

## 2. Implement and exercise the real result

Choose meaningful uncovered behaviors and real/substituted interactions under IMPLEMENTATION.md. Follow its behavioral red/green or justified alternative, implement directly in approved owners, update required callers/tests/documentation and complete the authorized cutover. Recover repository facts yourself; route missing design decisions upstream rather than inventing them.

Run applicable static, behavioral, regression, required-suite and actual-runtime checks, including assigned macro flows. A direct unit owns the entire final target and combined evidence; a ticket excludes only explicitly later-owned flows. Preflight full conformance and repair known defects before submission. Missing mandatory verification blocks Pass.

Apply the specification-authority gate below to every specification write, including ticket status/role/evidence metadata. Ordinary authorized code-only conformance repairs remain automatic.

## 3. Repeat review and original-implementer repair

The assigned writer alone persists layout-defined records under `review-records`; the reviewer returns reports without editing. Record the identified submission and actual repair/verification evidence and limits before review. Use [reviewer-prompt.md](reviewer-prompt.md) with complete current inputs. Save every report before acting or advancement; record finding-linked repair decisions/evidence before re-review and reviewer dispositions before dependent work or handoff. The original implementer repairs, then the **same reviewer** checks complete current scope, prior findings and regressions. Repeat until Pass without findings/blockers. The reviewer alone disposes findings and corrects incomplete reports; authors leave repairs awaiting review and later diffs never narrow scope. Resumed unchanged results still need current independent assessment, though unchanged evidenced human acceptance may remain applicable.

Continue authorized code repairs without extra permission, expose consequential autonomous decisions, and gate specification repairs as above. Retrieve accessible evidence or restore available tools before declaring an external blocker. Source changes immediately invalidate affected evidence even if metadata correction awaits confirmation; reconcile and renew affected checks/review, preserving justified unaffected evidence. Stalled progress requires the actual missing obligation/evidence/decision, not role rotation, a retry cap or a lowered gate.

## 4. Hand off at the authorized boundary

Persist Pass and obtain confirmation for any exact ticket execution-block update. Return scope, source/code identity, actual evidence/limits, consequential repair decisions and record references.

- **Delegated:** return to the controller without per-unit acceptance or `delivery.md`. Ticket Pass is local; the direct full-change Pass is already final independent review.
- **Standalone:** use IMPLEMENTATION.md's delivery content, request explicit final human acceptance of the exact reviewed scope, and record the actual decision before updating acceptance. Earlier direction, write consent or repair approval is not final acceptance; revisions return through the original pair and affected verification.

Stop at this handoff or a precise external blocker after reachable authorized work. Do not launch another unit, commit, merge, push, close trackers or release automatically.

## Specification authority and evidence validity

Before **every** creation, edit, move, deletion or reorganization of an entry, model, ticket or canonical specification, the assigned original author must display the exact content/patch, destinations, current basis, deletions and consequences, obtain explicit human confirmation, then apply only that content. This includes metadata, formatting, typos, synchronization, migrations and reverts, without inferred exceptions. A fully displayed multi-file batch may be confirmed once; direction, Pass, authority to work or “continue” never approves unseen text or dependent decisions. Keep unconfirmed proposals conversational, not candidate drafts or log workarounds.

Immediately before applying, recheck both basis and proposed content against the concrete confirmation; either changing requires renewed confirmation. Resumption and delegates must recover that evidence, not remembered consent. Supply prior concrete confirmations to reviewers even for newly written specifications. Final human approval is distinct and binds the exact reviewed result and sources; it may simultaneously approve a fully displayed exact metadata patch. Authorized code-only fixes and factual admitted records bypass this specification gate, but cannot amend specifications indirectly.

Use exact current result/source identities, including relevant dirty/untracked code. Approval/status metadata may stay outside the reviewed digest, or explain a metadata-only difference. Substantive source, result, scope, membership or obligation changes immediately invalidate affected evidence and approval even while status correction awaits permission; preserve unaffected approval only with an actual impact basis. Recover comparison evidence rather than treating a digest as a historical snapshot. For legacy mixed artifacts, require exact migration confirmation and attributable provenance; unknown provenance blocks the affected migration, not unrelated work.
